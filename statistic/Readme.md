## 2. 「経験・勘・度胸」を数学で説明する

この部分が教材の知的な中心になります。

ただし、経験・勘・度胸がそのまま一対一で数学に置き換わるわけではありません。それぞれを、数学的に扱える要素に分解するのが適切です。

## 経験・勘・度胸の工学的解釈

① 経験 → 統計

過去に何が起きたか。どんな条件で成功・失敗したか。

\\[ \text{経験} \rightarrow \text{観測データ・分布・傾向} \\]

例：100回の作業で何回失敗したか。失敗がどの条件で多かったか。

② 勘 → 確率・仮説

まだ確定していないが、何かがおかしいと気づく。

\\[ \text{勘} \rightarrow \text{仮説・条件付き確率} \\]

例：機械の音が少し違う。故障の可能性が高まったのではないか。

③ 度胸 → 意思決定・危機管理

不確実な状況で、どの行動を選ぶか。

\\[ \text{度胸} \rightarrow \text{期待損失・判断基準} \\]

例：生産を続けるか、停止して点検するか。

ここで、視聴者に覚えてもらう数式は一つで十分です。

リスクの基本的な考え方

\\[ R=P(\text{事故})\times L(\text{損失}) \\]

P：事故の発生確率、L：発生した場合の損失。単純化した期待損失のモデルです。

例えば、機械の故障確率が1%で、故障した場合の損失が100万円なら、

\\[ 0.01\times1,000,000=10,000\text{円} \\]

期待損失は1回当たり1万円です。

これなら、点検費用や予防保全費用と比較して、対策を考えられます。

ただし、重大事故では平均的な期待損失だけで判断してはいけません。死亡・人身事故など、許容できない結果については、別途安全上の制約や対策基準を設けます。

### ここで伝えるべき重要なこと

- 経験は、データの蓄積になる。
- 勘は、異常の発見や仮説を作る能力になる。
- 度胸は、不確実性の中で判断し、行動する能力になる。

つまり、ベテランは単に長く働いた人ではありません。大量の経験から、まだデータになっていない異常を発見できる人なのです。

# 4. 人間と生成AIの役割分担

ここは、教材のメッセージを最も強く打ち出す部分です。

従来の自動化は、人間が行っていた作業を機械に置き換えるという考え方が中心でした。

しかし、生成AIの活用では、別の考え方ができます。

| 人間が担当すること    | 生成AIが支援すること  |
| ------------ | ------------ |
| 問題を発見する      | 過去の類似問題を探す   |
| 新しい仮説を考える    | 仮説を比較・整理する   |
| 現場で異常を感じる    | センサー・記録を分析する |
| 価値や優先順位を判断する | 判断材料を提示する    |
| 新しい方法を試す     | 実験結果を整理する    |
| 結果に責任を持つ     | 判断根拠や履歴を記録する |

特に重要なのは、次の違いです。

人間は、何を問題とするかを発見する。AIは、蓄積された知識を利用して問題解決を支援する。

ただし、AI自身も新しい仮説や問題候補を提示できます。人間だけが創造できるという意味ではありません。問題の定義、価値判断、安全上の許容範囲、最終的な責任は、人間と組織が担う必要があります。

また、生成AIに学習させるとは、必ずしも毎回モデル自体を追加学習させることではありません。

- 記録を検索できるようにする（RAG）
- 判断事例をデータベース化する
- 良い回答例で追加学習する（SFTなど）
- 作業の結果から評価・改善する

このような複数の仕組みを含めて考えると、現実的です。

# 6. 教材に使うデータの設計

動画を単なる精神論にしないために、実際に数字を使った例を入れます。

例えば、工場の機械の故障を考えます。

次のような仮想データを教材用に用意します。

| 状態      | 故障件数 | 検査件数  | 故障率   |
| ------- | ---- | ----- | ----- |
| 通常時     | 2    | 1,000 | 0.2%  |
| 異音あり    | 12   | 200   | 6.0%  |
| 振動増加    | 15   | 150   | 10.0% |
| 異音＋振動増加 | 20   | 100   | 20.0% |

説明用の架空データです。実際の故障率を示すものではありません。

これを使えば、次のような教材展開ができます。

1. 熟練者が異音に気づく。
2. 振動の増加にも気づく。
3. 過去の故障記録を調べる。
4. 異音と振動の組み合わせで故障率が高いことを発見する。
5. 故障する前に点検する仕組みを考える。
6. この判断を記録して生成AIで再利用する。

ここで一つ、統計教育上の注意があります。

上の表だけでは、異音と振動が独立しているか、同じ故障原因によるものか、因果関係があるかは分かりません。母数、観測期間、機械の種類、検査条件も必要です。

この点をあえて教材に入れると、統計とは数字を並べることではなく、数字の意味を考えることだと伝えられます。

## 生成AIに渡すデータの基本構造

例えば、ベテランの判断を次のようなデータとして残します。

```
{
  "case_id": "MACHINE-001",
  "observation": {
    "sound": "通常と異なる異音",
    "vibration": "通常より増加"
  },
  "hypothesis": [
    "軸受の劣化",
    "回転部の異常"
  ],
  "decision": "運転停止して点検",
  "reason": "故障拡大と二次被害を防ぐ",
  "action": "振動測定と軸受点検",
  "result": "軸受の劣化を確認",
  "lesson": "異音と振動増加の同時発生に注意"
}
```

このデータには重要な意味があります。

単に「故障した」という結果だけではなく、

- 何を観察したか
- 何を推測したか
- どう判断したか
- 何を実行したか
- その結果はどうだったか

という人間の思考過程を残しています。

これが、生成AIにとって価値のある教材データになります。

ただし、判断記録には誤りや思い込みも含まれます。成功事例だけでなく、失敗事例、判断の不確実性、反対意見、適用条件も記録し、検証してから活用することが重要です。

# 7. 全体を貫く論理モデル

## 人間とAIによる知識創造サイクル

1. 人間が現場で経験する

   現象・失敗・成功・違和感を発見する。
2. 人間が仮説を作る

   経験と勘を使い、原因や対策を考える。

   データを分析し、リスクを評価する。

   判断の根拠、条件、結果を保存する。
5. 生成AIで再利用する

   類似事例を探し、知識を組み合わせる。
6. 人間が新しい課題に挑戦する

   AIの回答を検証し、新しい経験を作る。

新しい経験が、次の知識になる。

人間 → 知識化 → 生成AI → 人間という循環が続く。

このモデルは、従来の業務改善におけるPDCAだけでなく、知識の創造と再利用を含むものです。

# Q2 リスクの理解で、IEC HAZOPの１１のGuide Wordを入れてくkださい。

A2 

ぜひ入れましょう。むしろ、IEC HAZOPのGuide Word（ガイドワード）11種類を入れると、教材の「経験・勘・度胸を工学的に表現する」という主張に、具体的な分析方法が加わります。

特にHAZOPは、熟練者の「何かおかしい」「いつもと違う」という勘を、体系的な問いに変換する教材として適しています。

# 1. IEC HAZOPの11のGuide Word

HAZOPでは、設計意図や正常な状態に対して、Guide Wordを組み合わせて逸脱（Deviation）を体系的に検討します。

| No. | Guide Word | 日本語の意味   | 考える質問            |
| --- | ---------- | -------- | ---------------- |
| 1   | NO / NOT   | なし・否定    | あるべきものが存在しなかったら？ |
| 2   | MORE       | 増加・過剰    | 多すぎたら？           |
| 3   | LESS       | 減少・不足    | 少なすぎたら？          |
| 4   | AS WELL AS | 付加       | 余計なものが加わったら？     |
| 5   | PART OF    | 一部・不完全   | 一部分しか実行されなかったら？  |
| 6   | REVERSE    | 逆転       | 方向や順序が逆になったら？    |
| 7   | OTHER THAN | その他・別のもの | 想定したものと違ったら？     |
| 8   | EARLY      | 早すぎる     | 予定より早く起きたら？      |
| 9   | LATE       | 遅すぎる     | 予定より遅く起きたら？      |
| 10  | BEFORE     | 前に       | 想定した順序より前に起きたら？  |
| 11  | AFTER      | 後に       | 想定した順序より後に起きたら？  |

※IEC 61882のHAZOPで用いられる代表的な11のGuide Wordです。適用する設計意図やパラメータによって、組み合わせの適否は異なります。

# 2. HAZOPを使った具体例：工場の搬送装置

11個を暗記するだけでは、教材として十分ではありません。

一つの機械を題材に、11種類の問いを実際に適用するのが効果的です。

設計意図（Design Intent）

「搬送装置が、決められた部品を、決められた方向に、決められた速度で、決められた順番とタイミングで搬送する」

この設計意図に対して、11種類のGuide Wordを適用します。

| Guide Word | 搬送装置で考える逸脱      | 想定される問題 |
| ---------- | --------------- | ------- |
| NO / NOT   | 搬送しない           | 生産停止    |
| MORE       | 速度が速すぎる         | 部品衝突・落下 |
| LESS       | 速度が遅すぎる         | 生産遅延    |
| AS WELL AS | 予定外の部品も搬送する     | 異品混入    |
| PART OF    | 部品の一部分しか搬送しない   | 不完全な組立  |
| REVERSE    | 逆方向に搬送する        | 衝突・設備破損 |
| OTHER THAN | 指定外の部品を搬送する     | 誤組立     |
| EARLY      | 予定より早く搬送する      | 前工程との干渉 |
| LATE       | 予定より遅く搬送する      | 後工程の停止  |
| BEFORE     | 前工程完了前に搬送する     | 未完成品の流入 |
| AFTER      | 必要な工程順序より後に搬送する | 工程順序の異常 |

ここで重要なのは、Guide Wordは単に故障の種類を並べたものではないということです。

人間が思いつかなかった異常を、決められた質問によって発見する仕組みです。

これは、経験と勘を工学的な手順に変換する好例です。

1\. HAZOPの11語は、正確な説明を別途補足する

第四話の11語は短い動画用の要約です。IEC 61882では、基本的なガイドワードと時間・順序に関する追加のガイドワードを区別して扱います。特に「早すぎる／遅すぎる」と「前に／後に」は同じ意味ではありません。授業用スライドでは、コンベアの設計意図を使って違いを説明するとよいでしょう。

2\. 生成AIを「学習」と「知識の利用」に分ける

第七話で紹介したRAGは、毎回AIの基盤モデルを再学習する仕組みではありません。既存の知識を検索し、回答の材料として使います。SFT（教師ありファインチューニング）などのモデル自体を調整する方法とは区別して教えると、技術的に正確です。

3\. 8話の後に、視聴者が自分の経験を記録する課題を設ける

例えば、「自分が経験した、いつもと違うこと」を一つ選び、次の5項目を書いてもらいます。
